## 2. A. M7 评测体系（SP-EVAL-001~003，P1）

### 2.1 SP-EVAL-001 测试集加载
- **规格**：`data/test_cases/` 支持 `intent.csv`、`retrieval.jsonl`、`chat_e2e.jsonl` 三种格式；非法行跳过并计数报告。
- **现状**：`data/test_cases/intent.csv` 已有（M3 生成 300 条）。**缺**：`retrieval.jsonl`（标注 q → gold_docs 列表）、`chat_e2e.jsonl`（对话对）。
- **实现**：`app/eval/case_loader.py` —— `load_intent_cases()` / `load_retrieval_cases()` / `load_chat_cases()`，非法行（缺字段/坏 JSON）跳过并返回 `(cases, skipped_count)`。
- **数据生成**：`scripts/gen_eval_data.py`（确定性种子）——retrieval 样例 50 条（查询 + 期望 doc_id，基于 `data/raw_docs` 扩充后的知识库）、chat_e2e 样例 20 条（含正常/澄清/转人工/退款路径）。
- **测试**：`tests/unit/test_case_loader.py` → `T-EVAL-101`（加载计数）、`T-EVAL-102`（非法行跳过计数）。
- **DoD**：三种格式加载全绿；非法行报告准确。

### 2.2 SP-EVAL-002 指标计算
- **规格**：意图 Accuracy/宏F1/混淆矩阵；检索 Recall@5/MRR/NDCG@5；RAGAS faithfulness/answer_relevancy；结果写入 `eval_runs`。
- **实现**：
  - `app/eval/metrics.py`（纯函数）：`accuracy`、`macro_f1`、`confusion_matrix`、`recall_at_k`、`mrr`、`ndcg_at_k` —— 全部可手工样本验证；
  - `app/eval/ragas_eval.py`：faithfulness / answer_relevancy 走真实 LLM（DeepSeek 主）；**无 key 时 skip**（同 T-RET-201 模式）；
  - `app/eval/runs.py`：`eval_runs` 落 PG（复用 models/db.py，新增表 `eval_runs`）。
- **测试**：`tests/unit/test_metrics.py` → `T-EVAL-201`（Recall@5 手工样本验证）+ MRR/NDCG 各 1 例。
- **DoD**：指标函数全绿；eval_runs 可读写（内存 repo + PG 守卫双测）。

### 2.3 SP-EVAL-003 消融实验跑批
- **规格**：一键跑 E1~E5（仅BM25 / 仅向量 / RRF / RRF+重排 / 动态权重），输出对比表 JSON，可被前端看板渲染。
- **实现**：`app/eval/ablation.py`——基于 `retrieval.jsonl` 对 5 种策略分别跑 Recall@5/MRR/NDCG@5，产出 `[{strategy, recall@5, mrr, ndcg@5}]`；重排策略依赖 `RERANKER_API_KEY`（无 key 该列标记 `skipped`，不阻塞）。
- **测试**：`tests/integration/test_ablation.py` → `T-EVAL-301`（5 组策略均可执行；ES 守卫）。
- **前置依赖**：ES 在线 + 知识库已索引（见 F/G）。
- **DoD**：5 组策略跑通；对比表 JSON 结构稳定。

## 3. B. M8 前端页面（SP-FE-001~003）

### 3.1 技术栈与骨架
- Vue 3 + Vite + Element Plus + Pinia（设计文档 §8）；目录 `frontend/`；构建产物由 FastAPI 托管（SP-DEP-001 多阶段构建打进 `app/static`）。
- 开发期：Vite dev server 代理 `/api/v1` → `http://localhost:8000`。

### 3.2 SP-FE-001 对话页（P0）
- **规格**：消息气泡 + Markdown 渲染 + SSE 流式打字机；快捷指令；消息带引用角标 `[n]` hover 显示来源片段。
- **实现要点**：
  - `frontend/src/api/chat.js`：`fetch` + `ReadableStream` 解析 SSE（`event:`/`data:`/`id:` 行，携带 `Last-Event-ID` 重连）；
  - `frontend/src/components/ChatMessage.vue`：Markdown 渲染（`marked` + DOMPurify 防 XSS）、角标 `[n]` hover 弹层展示 `retrieval` 事件中的 docs；
  - `frontend/src/components/QuickActions.vue`：快捷指令（查物流/退款/转人工…）。
- **测试**：`frontend/src/**/*.spec.js`（Vitest 单测：SSE 解析器、事件状态机）；Playwright 冒烟 `tests/e2e/test_frontend.spec.js`（P1，时间不足可只保对话页+追踪面板）。

### 3.3 SP-FE-002 追踪面板（P0）
- **规格**：接收 SSE `intent/route/retrieval/tool_call` 事件渲染时间线（意图+置信度、检索 Top5+分数、工具参数与结果、每步耗时）；消息流与时间线自动滚动。
- **实现要点**：`frontend/src/components/TracePanel.vue` —— 以 `id:` 序号为 key 累积事件，`retrieval.docs` 渲染 Top5（chunk_id/标题/分数），`tool_call` 渲染参数与结果 JSON。
- **测试**：Vitest 事件→时间线渲染逻辑；Playwright 冒烟。

### 3.4 SP-FE-003 评测看板与工单页（P1）
- **规格**：评测看板渲染 `eval_runs` 指标卡与消融对比表；工单页列表/详情/审计回溯/状态流转展示（**流转仅限受限迁移**：APPROVING→APPROVED/REJECTED，不得直接触发 REFUNDING）。
- **实现**：`frontend/src/views/EvalBoard.vue`（数据源：`GET /api/v1/eval/runs` 新端点，M7 交付）、`frontend/src/views/Tickets.vue`（对接 M6 `GET /tickets`、`GET /tickets/{id}/audit`、`POST /tickets/{id}/transition`，下拉仅展示受限迁移）。
- **测试**：工单页流转按钮与受限迁移约束的 Vitest 单测；冒烟同上。

### 4.2 SP-DEP-002 配置外置
- **规格**：所有密钥/地址仅来自环境变量；`docker-compose.yml` 无明文密钥；`.env.example` 不含真实值。
- **现状**：`.env.example` 已就绪（无真实值）；需补 `EVAL_RUNS` 相关与前端 `VITE_API_BASE` 文档。

### 4.3 SP-DEP-003 Nginx 与限流（P1）
- **规格**：Nginx 反代 + `limit_req`（默认 30 req/s）+ gzip（`text/event-stream` 除外）+ HTTPS（自签演示）；SSE 需 `proxy_buffering off` 与 `proxy_read_timeout ≥ 120s`；限流命中 429 时经 `error_page` 返回统一 JSON（`code=4290`）。
- **实现**：`deploy/nginx.conf`；`error_page 429` → 自定义 JSON（复用 SP-API-GEN 包装）。
- **测试**：`T-DEP-301`（Nginx 层压测触发 4290 且响应体为统一包装）；`bench_chat` 直连 app 端口（20 并发不受限流影响，SP-CHAT-003）。

## 11. 技术债与已知限制（不影响交付，但需记录）

1. **graph 每请求构建**：`run_chat_flow` 每次请求 `build_graph(deps)`（毫秒级），可缓存 compiled graph（按 deps 实例）。
2. **真实 Function Calling 未端到端验证**：M5 的 `OpenAICompatToolParser` 有 MockTransport 单测，但真实 LLM 的 tool_calls 解析待 H 联调；当前编排以 `extract_order_id` 规则提取为主。
3. **message 事件为单次 delta**：`delta=true` 一次全量 + `delta=false`；真流式（token 级增量）需 LLM stream 支持（可选增强，不影响协议正确性）。
4. **graph 状态回放为进程内**：CONFIRM 挂起已用 Redis pending 持久化；如需跨重启恢复图状态，可接入 LangGraph RedisSaver（M9 后按需）。
5. **RAGAS 指标依赖真实 LLM**：SP-EVAL-002 的 faithfulness/answer_relevancy 无 key 时 skip（有规则版 `check_faithfulness` 兜底）。
